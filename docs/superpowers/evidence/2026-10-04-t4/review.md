# T4 独立审查与处置

审查范围：以 `3cd117e846d89541dfd1b339769cc2a086997318` 为基线的全部 T4 改动。审查者为独立上下文的 `t4_review`（gpt-6-astra），只读审查；以下为审查反馈归纳与主线程处置，并非逐字引文。

## 发现与一次修复

- Critical：无。
- Important：持久 HLS 将旧绝对源路径当作永久身份，源改名后恢复与 HTTP 校验失败。新增目录 `HLSSource`，以稳定 recording_id/source_version 找当前已核验来源；manifest 的 SourcePath 仅保留为历史提示。Recover 比较稳定身份，不要求旧路径相等。HTTP 回归覆盖改名、旧路径被其他文件占用和新路径源替换；阶段回归覆盖先 T3 主 MP4 准备、再 HLS、源改名后无 FFmpeg 复用。
- Important：发布意图落盘前进程退出，私有构建目录无人回收，长期占用空间。新增先落盘的构建所有权标记，重启持久任务取得 claim 与共享预算后，只清理同版本/同档位且不被 intent/ready 引用的有主半成品，并在空间准入前完成；未知、其他所有者及活跃任务目录保留。回归以独立子进程 `os.Exit(72)` 留下 1MB 半成品，证明 defer 没执行、重启安全清理；另测发布意图和完成产物保护。
- Minor（延期）：共享预算竞争唤醒没有 FIFO 或最大排队时长保证；现有预算来自 T3，本轮证明并发上限及取消，未证明长期公平性。

半成品回归初次 RED 使用直接构造的遗留目录；修复后加强为实际 os.Exit(72) 子进程，最终全量测试包含该加强版本。

两项 Important 先运行回归观察 RED（`red-review.log`），实现后 GREEN（`green-review.log`、`green-review-process.log`、`green-rename-main.log`），随后全量 make test 与相关包 race 均通过。按 executing-plans 进行一次修复，不安排第二次审查。

## 审查未判断的边界与主线程裁定

1. 手机/TV/浏览器实际解码：列待验，自动媒体核验与 HTTP 200/206 不能证明设备首帧。成本是实际设备兼容问题仍可能存在。
2. 真正断电、文件系统崩溃及 Windows/Linux 实机 Sync 语义：列待验，进程退出回归和交叉编译不能代替。成本是平台持久性仍须独立验证。
3. 同 UID 恶意进程在哈希核验后原位改写文件：当前保持受管理存储的信任边界；已验证同句柄传输与路径替换拒绝，不声称防御原位恶意写。成本是这种本地威胁需要额外隔离或不可变存储。
4. 生产规模排队/吞吐及长 GOP/长视频哈希成本：列待验，source 保留原始 GOP，测试短样例不能证明小时级资源曲线。成本是容量与响应延迟需用独立长样本评估。
5. 客户端能力选择、自动适配质量与 v2 会话：仍归 T5，本轮显式 profile 选择与旧接口兼容。成本是现在还没有统一会话能力决策。
6. 最终全仓验证：由主线程在修复后实际执行并读出退出码，不沿用审查者结论。六组最终命令均退出 0，详见 verification.json 与 final-*.log。
